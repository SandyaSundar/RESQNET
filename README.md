# RESQNET — Computer Vision Module

**AI-Powered Disaster Person Detection for Resilient Swarm Coordination**

> Turning disaster imagery into actionable visual intelligence for autonomous search and rescue.

## Overview

The RESQNET Computer Vision Module provides the visual perception layer for a decentralized, multi-agent drone coordination system designed for disaster response.

Using deep-learning-based object detection, the module analyses disaster imagery to identify potential people, localise detections within images, and extract confidence-scored bounding boxes. These outputs are designed to support downstream verification, search-area prioritisation, and coordination decisions across a distributed drone swarm.

The module targets imagery associated with **floods, earthquakes, and cyclones**, with an emphasis on evaluating detection performance under challenging disaster conditions.

## Core Capabilities

- **Deep-Learning-Based Detection:** Apply a pretrained YOLO object detection model to identify candidate people in disaster imagery.
- **Image Preprocessing:** Use OpenCV to prepare images for inference and visualise model predictions.
- **Spatial Localisation:** Extract bounding-box coordinates to represent each candidate's position within an image.
- **Confidence Scoring:** Associate detections with model-generated confidence scores to support downstream filtering and review.
- **Candidate Extraction:** Structure detection outputs for individual candidates, with image and candidate identifiers supplied or generated by the relevant pipeline.
- **Visual Evidence Generation:** Produce annotated images with bounding boxes for inspection and verification.
- **Backend Interoperability:** Prepare detection data for integration with the RESQNET backend through a defined API contract.
- **Search Intelligence:** Supply image-space detection evidence that can be associated with a drone or search sector when corresponding metadata is available.

## Detection Output Contract

The intended detection record can follow a structure such as:

```json
{
  "image_id": "flood_image_001",
  "detections": [
    {
      "candidate_id": "candidate_001",
      "class": "person",
      "confidence": 0.87,
      "bbox": {
        "x_min": 120,
        "y_min": 85,
        "x_max": 190,
        "y_max": 240
      }
    }
  ],
  "person_count": 1
}
```

*Illustrative schema only; actual field names and values must match the implemented output and agreed backend contract. Bounding-box coordinates are pixel positions within the image, not GPS coordinates.*

## Integration with RESQNET

The intended end-to-end workflow connects visual perception with mission-level decision-making:

1. **Scenario Selection:** The frontend selects a disaster scenario or search area.
2. **Image Acquisition:** The relevant image is supplied to the perception pipeline.
3. **Inference:** The YOLO model processes the image and identifies candidate people.
4. **Detection Packaging:** Bounding boxes, confidence scores, and available identifiers are structured into detection records.
5. **Backend Handoff:** Results are passed to the backend through the agreed interface.
6. **Verification and Prioritisation:** The wider system evaluates candidate findings and determines which areas require further investigation.
7. **Swarm Coordination:** Verified or appropriately prioritised information can inform drone task allocation and search planning.

**Coordinate distinction:** Image-space bounding boxes identify positions inside an image. Mapping a candidate to a real-world location requires additional information, such as georeferencing, drone pose, camera calibration, or other localisation metadata.

## Dataset and Evaluation Strategy

The project dataset is organised around three disaster categories:

- Earthquake
- Flood
- Cyclone

Detection performance should be evaluated against suitable labelled data using metrics such as:

- **Precision:** How many predicted detections correspond to labelled people.
- **Recall:** How many labelled people the model successfully detects.
- **IoU (Intersection over Union):** How closely predicted bounding boxes align with ground-truth boxes.
- **False-positive analysis:** How often background objects are incorrectly detected as people.

Evaluation on representative aerial imagery is essential because small targets, occlusion, debris, water, unusual viewing angles, and variable lighting can affect detection quality.

## Reliability and Safety Considerations

- Model predictions represent **unverified candidate detections**, not confirmed survivors.
- Confidence scores express model confidence; they are not probabilities of survival or rescue urgency.
- Small, distant, obscured, or low-resolution people may be missed.
- Background objects may produce false-positive detections.
- Drone identity, timestamps, search-sector identifiers, and geographic coordinates must come from the appropriate system components.
- Candidate findings require the verification process defined by the wider RESQNET architecture before being treated as confirmed.
